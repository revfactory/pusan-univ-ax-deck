# LAB-6 기대 결과

## 요청 1: 승인 요약 초안

| 칸 | 기대 결과 |
| --- | --- |
| [만든 것] | 프로젝트 이름(새별 민원 상담), 다루는 민원 두 가지. 시험 기록에 파일 이름이 없으면 「확인 필요」로 나온다 |
| [시험 결과] | 시험 기록의 숫자가 그대로 나온다. 완성본 기록이면 1판 10/12(규칙 시험 실패 1건), 2판 12/12(규칙 시험 실패 0건) |
| [남는 위험] | 시험 기록의 「남는 위험」 표가 옮겨진다([담당자 확인] 판단 기준 없음, 시험하지 않은 범위, 시험 환경) |
| [사람이 정할 것] | 시범 기간, 쓸 사람과 공유 범위(Plus 프로젝트 공유는 최대 10명), 발송 전 확인 방법. 기록으로 정할 수 없는 값은 「확인 필요」 |

강사 사전 실행(codex)에서 `완성본/시험기록_예.md`를 넣었을 때 승인 요약의 네 칸이 모두 나왔고, 시험 기록에 없는 숫자는 나오지 않았습니다. 시범 기간·공유 범위·발송 전 확인 방법은 팀장이 정할 것으로 나왔습니다. 1판의 규칙 시험 실패 건수(1건)는 요약에 옮겨지지 않았으므로, 내 시험 기록의 1판 줄과 견주어 빠진 숫자가 있으면 채웁니다. ChatGPT 화면에서 같은지는 강사가 미리 확인합니다.

## 직접 고치기

- [시험 결과]의 숫자를 시험 기록과 한 줄씩 대조한다. 요약이 「중간안」「재시험」 같은 과정을 섞어 쓰면 최종 숫자가 무엇인지 한 줄로 정리한다.
- 「확인 필요」 칸은 내가 제안 값을 적는다(예: 시범 기간 2주, 공유 범위 고객지원팀 담당자 4명, 발송 전 금액 대조는 담당자).

## 팀장 판정

| 판정 | 이런 경우 |
| --- | --- |
| 승인(조건 있음) | 질문 5개가 모두 「예」이고, 조건을 적는다(예: 「시범 2주 동안 금액 안내 답변은 발송 전 담당자가 규정과 대조한다」) |
| 수정 요청 | 요약의 숫자가 시험 기록과 다르거나, 남는 위험에 막는 방법이 없다 |
| 보류 | 규칙 시험 실패가 있다 |

판정은 사람마다 달라도 됩니다. 판정의 근거로 시험 기록 한 줄을 직접 대조했는지가 중요합니다.

## 막혔을 때

| 증상 | 할 일 |
| --- | --- |
| 내 시험 기록이 없다 | `완성본/시험기록_예.md`를 붙여 넣는다 |
| 승인 요약이 네 칸이 아니다 | 「[만든 것] [시험 결과] [남는 위험] [사람이 정할 것] 네 칸만 다시 써 줘」를 보낸다 |
| 요약에 시험 기록에 없는 숫자가 있다 | 지운다. 「시험 기록에 없는 숫자를 모두 찾아 줘」를 보내 확인해도 된다 |
| 시간이 모자란다 | `완성본/승인요약_예.md`를 읽고 판정카드로 판정만 한다 |
