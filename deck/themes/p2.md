# 파트 2 테마 안내서: 종이 오리기(크라프트지 콜라주)

- 대상: 파트 2 챕터를 만드는 제작 담당과 원고 담당
- 근거: `plan/themes.md` 3절(공통)과 5절(파트 2)
- 부품 코드: `deck/themes/p2.js`(맨 위 주석에 함수 목록), 색과 클래스: `deck/themes/p2.css`
- 본보기: `deck/p2/ch00.js`(스타일 프레임 7장), 시트: `deck/qa/p2-ch00/sheet_01.png`, `sheet_02.png`

## 1. 이 파트의 화면

크라프트지 바탕 위에 한서윤 주임이 실습하며 만든 것을 오려 붙인 화면이다. 민원 출력물, 규정집, 설계서, 시험표, 승인 요약이 흰 테두리를 두른 사진 조각과 크림색 종이 카드로 놓인다. ChatGPT 화면은 흰 테두리 인쇄물로 테이프에 붙인다(회전 0°). 본문은 크림 종이 위에 쓰고, 크라프트 위에는 짧은 이름표와 숫자만 쓴다. 주홍 색지는 사람의 결정, 승인 도장, 지금 단계에만 쓰고, 짙은 초록 색지는 통과와 완료에만 쓴다. 모든 조각은 위에서 들었다가 놓는 움직임으로 붙는다.

### 부품을 쓸 때 지킬 것

- 카드의 글자가 넘치면 부품이 `[DECK] 카드 글자가 넘친다` 경고를 내고 카드 둘레에 분홍 점선을 그린다. 시트에서 분홍 점선이 보이면 카드 크기나 배치를 바꾼다. 문구를 줄이지 않는다.
- 제목이 `maxLines`를 넘거나 전환 장 질문이 정한 줄 수를 넘으면 `[DECK]` 경고가 나온다. 경고는 `deck/qa/p2-chNN/report.json`의 `consoleErrors`에 남으므로 `shoot` 뒤에 확인한다.
- 줄이 바뀌는 자리는 부품이 균형 있게 나눈다(`text-wrap: balance`). 「만들 / 수 있다」처럼 뜻 단위가 갈리면 문구를 바꾸지 말고 `\n`으로 나눌 자리를 정한다(`ch00`의 7번 슬라이드).
- 인물 네 명은 얼굴을 그리지 않는다. 머리 모양(단발, 짧은 머리, 넥타이, 사원증 줄, 묶은 머리)과 기호(말풍선, 도장, 자물쇠, 깃발)로 구분한다. 도장 기호만 주홍이다.

## 4. 슬라이드 유형별 구성

| 유형 | 배치 |
| --- | --- |
| `title` | `THEME.videoTitle(el, { kind: 'intro' })`. 영상이 화면 전체, 왼쪽의 크림 띠 위에 레몬 꼬리표(「파트 2」), 88px 음절 조각 제목, 40px 파트 질문. 띠 너비는 가장 긴 줄 끝에서 90px까지다(최소 글자 폭 760px, 최대 1100px) |
| `transition` | `THEME.videoTitle(el, { kind: 'chapter' })`. 꼬리표 「파트 2 · N장」, 72px 제목, 40px `entry` 질문. 영상 배정과 반전은 `plan/themes.md` 7절 표를 따른다(`flip: true`면 띠가 오른쪽으로 간다) |
| `story` | 큰 사진 조각 하나(`cutout`) + 인물 실루엣(`person`) + 크림 카드에 대사. 대사 카드는 인물 쪽으로 붙인다 |
| `concept` | 크림 카드 2\~3장을 조금씩 겹쳐 놓는다. 카드마다 한 가지 내용, 번호 조각(`num`), 필요하면 사진 조각(`photo`) |
| `diagram` | 크림 종이(`paper`)를 칸으로 나누고(`grid`) 칸마다 조각을 하나씩 붙인다. 화살표 대신 조각을 놓는 순서로 흐름을 보인다. 설계서 다섯 칸(ch03)이 이 형식이다 |
| `data` | 크림 종이를 오린 막대(`paper`, `torn: 'right'`)와 Anton 숫자. 막대 그래프를 따로 그리지 않는다. 고른 항목에는 주홍 테이프 |
| `demo` | 대화창·터미널을 `THEME.shot`의 인쇄물로 놓는다(회전 0°). 터미널은 `draw`에서 `KIT.terminal`을 쓴다. 짚을 곳은 `marks` |
| `lab-step` | 바탕 `'lab'`. 왼쪽 위에 단계 번호 조각(`step`), 그 오른쪽에 할 일을 쓴 제목 띠, 가운데에 화면(`shot`, `wide`), 오른쪽에 프롬프트 카드(`bodyClass: 'p2-prompt'`, 36px)와 초록 기대 결과 카드 |
| `lab-check` | 바탕 `'lab'`. 확인할 항목을 `flip` 카드로 두고, 키를 누르면 넘겨서 기대 결과를 보인다 |
| `quiz` | `flip` 카드. 앞면 크림(질문), 뒷면 초록(답). `flipAt`을 `steps` 다음 시각에 둔다 |
| `recap` | 크림 카드를 한 장씩 놓고, 끝난 항목에는 초록 테이프 대신 초록 번호 조각(`numTone: 'green'`)을 쓴다 |

### 화면 캡처

- 캡처 파일은 `deck/assets/p2/shots/<슬라이드 id>.png`다. 파일이 있으면 `THEME.shot(el, '../assets/p2/shots/<id>.png', { size })`로 넣는다.
- 파일이 없으면 `src`에 `null`을 주고 `sidebar`·`chat`·`draw`로 같은 틀에 화면을 그린다. 없는 경로를 걸어 두면 점검에서 ✗가 난다.
- 그린 화면의 대화 글자는 34px, 사이드바 글자는 30px이다. 버튼 이름과 메뉴 이름은 `plan/tool_facts.md`의 표기를 그대로 쓴다(예: 「새 프로젝트」).
- 짚을 곳은 `marks: [{ x, y, w, h, n, at }]`로 준다. 좌표는 틀 안 화면 기준 비율(0\~1)이다. 캡처로 바꿔도 같은 자리를 짚도록 캡처를 틀 비율로 잘라 넣는다.
- 캡처를 넣은 슬라이드도 버튼 이름과 입력할 글을 옆의 크림 카드에 36px로 다시 쓴다.

### 영상과 그림이 들어오기 전

- `videoTitle`에 `src`·`poster`를 주지 않으면 오른쪽 40%에 종이로 그린 콜라주가 놓인다. `scene`은 영상에 맞춘다: `p2-intro`는 `'intro'`, `p2-tr-place`는 `'place'`, `p2-tr-flip`은 `'flip'`, `p2-tr-swap`은 `'swap'`.
- 영상이 들어오면 `src: '../assets/video/p2/<id>.mp4', poster: '../assets/video/p2/<id>.jpg'`를 준다. 영상은 없고 시작 그림만 있으면 `poster`만 준다(예: `'../assets/img/p2/p2-key-intro.jpg'`, 10초에 걸쳐 3% 확대된다).
- 대표 그림·영상에는 `saturate(.75) brightness(1.05)` 필터가 걸린다(`p2.js`의 `MEDIA_TONE`). 그림 속 크라프트(#CC8E53 안팎)를 테마 바탕(#C69C6D)에 맞춰 전환 장과 본문 장의 바탕색이 이어지게 한다.
- `cutout`에 `src`가 없으면 `fallback`의 종이 그림이 같은 자리에 놓인다. 그림이 들어오면 `'../assets/img/p2/<id>_cut.png'`를 준다. 부품이 PNG의 투명 여백을 빼고 자리에 맞추며, 흰 테두리는 화면의 2배 해상도 캔버스에 미리 그려 둔다.
- 대표 그림 누끼와 쓰임: `p2-key-printout` 민원 출력물, `p2-key-binder` 규정집, `p2-key-laptop-hands` 실습하는 손(시험 실행), `p2-key-stamp` 도장. 시험표 누끼는 없다. 시험표를 사진 조각으로 보여야 하면 `fallback: 'table'`의 종이 그림을 쓴다.

| 음절 조각 붙이기 | 파트·챕터 제목만. 음절마다 크림, 레몬, 초록, 연한 크라프트 색지 조각이 붙고, 받침은 0.05초 늦게 따로 붙는다. 조각 간격은 0.07초, 글자가 많으면 전체가 1.1초 안에 끝나도록 줄어든다 |
| 슬라이드 제목 | 크림 띠 한 장(줄이 여럿이면 줄마다 한 장)이 들었다 놓인다. 한 색으로 쓴다 |
| 배경 | 끝 상태에서는 크라프트 위의 밝은 자리만 `ctx.amb`로 아주 느리게 옮겨 간다 |

- 슬라이드에 들어오고 0.3초 안에 머리말과 바탕 종이가 놓이기 시작한다. 핵심 문장은 1.5초 안에 다 놓이게 `at`을 잡는다.
- 이웃한 슬라이드가 같은 등장을 세 번 넘게 잇지 않게, 조각 수와 순서(위에서 아래, 왼쪽에서 오른쪽, 큰 조각 먼저)를 슬라이드마다 바꾼다.
- 이 파트에서 쓰지 않는 움직임: 흐림 등장, 빛 효과, 옆에서 미끄러져 들어오는 등장(종이는 위에서 놓는다), 통통 튀는 넘침(`ease.pop`, `outBack`), 카메라 회전, 투명도만 바꾸는 등장.

### 주홍을 제목 조각에서 뺀 이유

`plan/themes.md` 5절은 제목 음절 조각의 색에 주홍을 넣었지만, 3절은 주홍을 「승인과 사람의 결정에만」 쓰도록 정했다. 제목마다 주홍 조각이 섞이면 승인 장면의 주홍이 눈에 띄지 않는다. 그래서 음절 조각의 기본 색을 크림, 레몬, 초록, 연한 크라프트로 두었다. 다른 색 묶음이 필요하면 `THEME.title`의 `tones`로 준다.

## 7. 하지 않는 것

1. 크라프트 바탕 위에 본문을 바로 쓰지 않는다. 본문은 크림 카드 위에 쓴다. 크라프트 위에는 짧은 이름표, 숫자, 머리말만 둔다.
2. 주홍을 장식으로 쓰지 않는다. 사람의 결정, 승인 도장, 지금 단계, 짚는 고리, 고른 항목의 테이프에만 쓴다.
3. 화면 캡처와 프롬프트 카드를 기울이지 않는다. 참가자가 따라 읽는 글은 회전 0°, 36px 이상이다.
4. CSS `transition`·`animation`·`@keyframes`, 화면 전체 흐림, 비네트·필름 그레인, 모서리 브래킷, 영문 대문자 라벨을 쓰지 않는다. 종이 결은 테마가 처음에 한 번 캔버스로 만든 무늬만 쓴다.
5. 없는 그림·영상·캡처 경로를 걸어 두지 않는다. 파일이 없으면 테마의 대체 표시(`fallback`, 콜라주, 그린 화면)를 쓰고 보고한다.

## 8. 레이아웃 목록

2026-11-24에 더했다. 완성 덱을 본 사용자가 두 가지를 지적했다. 한 장에서 키를 너무 많이 눌러야 하고, 한 파트 안의 레이아웃이 단조롭다는 것이다. 실제로 6장은 12장 가운데 11장이 키를 2\~4번 눌러야 했다. 실습 단계 7장은 모두 「왼쪽 위 번호, 가운데 그린 화면, 오른쪽 작은 카드 두세 장」 구도였고, 카드 글자는 30\~34px로 빽빽했다. 크라프트 바탕, 종이 조각, 테이프, 색은 그대로 두고 한 장 한 장의 구도를 아래 목록에서 고른다.

### 규칙

1. 같은 레이아웃을 두 장 잇달아 쓰지 않는다. 한 챕터에서 다섯 가지 이상을 쓴다.
2. 장마다 가장 중요한 요소 하나를 정한다. 그 요소(종이 한 장이나 한 묶음)가 화면의 3분의 1 이상(691,200px² 이상, 예: 960×720)을 차지하게 한다. 핵심 요소는 세로로 y 200\~980을 쓴다.
3. 끝 상태에서 화면의 위쪽 절반이나 아래쪽 절반이 비어 있으면 안 된다.
4. 제목 띠는 80px(실습 단계 번호가 있으면 68px)이다. 핵심 숫자는 Anton 180px 이상이다. 종이 안 설명 글자는 34px 이상이고, 새 부품의 기본값은 40\~44px다.
5. 보조 안내는 줄인다. 원고 `onScreen`의 문구는 빼지 않는다. 한 장에 다 들어가지 않으면 글자를 줄여 넣지 말고, 챕터 배정표에 적어 리더에게 알린다.
6. 키 누름: `steps`는 기본 `[]`다. 모든 요소가 키 누름 없이 차례로 나타나 3\~4초 안에 끝 상태가 된다. 답을 먼저 보이면 안 되는 장(퀴즈 정답, 손들기 뒤에 보이는 결과, 앞뒤 대비의 뒤쪽)에만 시각 하나를 둔다. 둘 이상은 두지 않는다. 그 한 번은 부품의 `revealAt`(또는 `flipAt`)으로 크게 보인다: 종이가 1.22배와 큰 그림자에서 0.45초 동안 붙거나, 카드가 넘어간다. `revealAt`은 `steps` 시각보다 0.1초 뒤에 둔다.
7. 실습 단계 장은 무엇이 중심인지에 따라 구도를 고른다.

| 중심 | 레이아웃 |
| --- | --- |
| 화면에서 누를 곳 | 화면 크게 |
| 복사해 보낼 요청문 | 요청문 크게 |
| 보낸 뒤 나와야 하는 결과 | 기대 결과 크게 |
| 채점 기준, 판정 기준 | 채점 기준, 판정 순서 |
| 결과 견주기 | 큰 숫자, 좌우 대비, 손들기 |
| 기록 양식 | 표 한 장 |

8. 실습 단계 장 한 장에 쪽지(`callout`, `note`, 작은 `card`)는 세 장까지 둔다. 그보다 많으면 장을 나누거나 강사 메모로 옮긴다. 제목 띠 옆이나 아래의 띠 한 줄(`strip`)은 쪽지로 세지 않는다. 띠도 한 장에 한 줄만 둔다.

### 부품을 쓸 때 지킬 것

- 배경(`THEME.bg`)을 가장 먼저 만든다. 나중에 만들면 앞서 만든 제목과 화면을 덮는다.
- 종이 안 글자가 넘치면 부품이 `[DECK]` 경고를 내고 분홍 점선을 그린다(`versus`, `sequence`, `handsUp`, `result`). 화면 아래로 넘치면 `checklist`, `decide`, `table`, `promptSheet`가 경고를 낸다. `shoot` 뒤 `report.json`의 `consoleErrors`가 비어 있어야 한다.
- 짚는 쪽지(`callout`)의 번호는 `shot`의 `marks` 번호와 같게 쓰고, 화면의 누를 곳을 가리지 않는 자리에 붙인다.
- 넘기는 질문은 기존 `THEME.nextQ`를 쓴다. 「한 문장」의 `sub`로 넣어도 된다.
