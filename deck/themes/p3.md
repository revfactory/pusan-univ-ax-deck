## 1. 이 파트의 화면

평평한 숯색 바탕(`#141414`)에 흰 글자를 쓰고, 구조와 강조는 넓은 주황 면(`#FF5B14`) 위의 검정 글자로 보인다. 장마다 가장 중요한 요소 하나를 화면의 3분의 1 이상으로 크게 둔다. 전환 장은 위쪽에 흑백 영상, 아래쪽에 화면 폭 전체의 주황 띠를 두고 띠 안에 제목을 쓴다. 승인은 연두(`#C6FF4A`) 고리와 이름표로만 보인다. 유리 판, 배경 흐림, 무지개 띠, 보라 빛, 빛 번짐을 쓰지 않는다.

## 2. 색, 팔레트, 서체

### 색의 역할

| 색 | 쓰는 곳 | 쓰지 않는 곳 |
| --- | --- | --- |
| 주황 면 `#FF5B14`(위 글자 `#141414`) | 단계 번호 칸, 「다음 질문」 면, 제목 막대, 큰 숫자, 전환 띠, 좌우 대비의 답 쪽 면, 카드 격자의 강조 칸 하나, 퀴즈 정답 칸, 지금 단계 칸 | 승인 표시, 본문 글자, 넓은 바탕 |
| 주황 글자 `#FF7A3D` | 카드 이름표, 칸 번호, 강조할 끝말 하나(`em`) | 밝은 면 위 |
| 주황 선 4px | 화면을 짚는 표시, 켜진 칸의 테두리(`chip.light`) | - |
| 연두 `#C6FF4A`(위 글자 `#141414`) | 승인 지점 고리의 채움과 체크, 승인자 이름표, 확인 목록의 통과 칸 | 승인과 관계없는 체크, 형광 강조, 경로, 글자 그림자 |
| 밝은 면 `#F7F7F5`(위 글자 `#141414`) | 짚는 말 이름표, 원문 종이(`doc`), 대화의 사용자 말 | 본문 바탕 |

- 한 장에 주황 면은 두 곳까지다. 제목 막대는 0.7초 안에 사라지므로 세지 않는다. 「다음 질문」이 있는 장은 다른 주황 면을 하나만 둔다. 확인 목록의 주황 ✕ 칸도 주황 면으로 센다.
- 「승인」을 뜻하는 것은 모두 연두다: 승인 지점 고리, 승인 체크, 승인자 이름표, 표의 승인자 칸, 확인 목록의 통과 칸. 구조와 강조는 주황이다. 승인을 주황 면으로 그리지 않고, 승인이 아닌 것을 연두로 그리지 않는다(2026-11-24 정함).
- 주황 면이 큰 장(큰 숫자, 전환 띠, 퀴즈 정답 칸)에서도 연두 표시는 작아도 색으로 구별된다.
- 칩 여러 개를 켜는 장은 `chip.light(v)`를 쓴다. 면이 아니라 테두리가 켜지므로 주황 면 수에 들지 않는다.
- 파트 1의 호박색(`#F2A93B`, 승인 색)과 다르다. 파트 3 주황은 빨강 쪽(색상각 약 18°)이고 넓은 면에 검정 글자로만 쓴다.

### 장 하나의 크기 기준(2026-11-24, 시범 챕터 ch05에서 정함)

새로 만드는 장은 `deck/p3/ch05.js`와 시트 `deck/qa/p3-ch05/sheet_01.png`·`sheet_02.png`를 크기의 본보기로 삼는다. 레이아웃 부품의 기본값은 이 기준에 맞췄다. 인자를 주지 않으면 아래 크기가 나온다.

| 대상 | 기준 |
| --- | --- |
| 장 제목 | 72px(`pageTitle`, y 146) |
| 핵심 요소의 자리 | y 240\~900 이상을 쓴다 |
| 설명 글자 | 34px 이상(보조 줄, 풀이, 이름표, 출처를 뺀 모든 글) |
| 강조 | 장마다 한 곳을 크게: 주황 면 하나 또는 100px 이상의 글자 |
| 승인 지점 고리 | 지름 150 안팎(`gates` 반지름 76), 고리 선 7, 고리 이름 40px, 풀이 34px, 승인자 이름표 34px, 묶음 이름 40px |
| 목록 항목 | 60px 이상(`points`, `checklist`) |
| 칸 이름 | 40px 이상(`split` 이름 40px, `tile` 제목 48px, `sequence` 이름 52px와 번호 120px) |

`THEME.title`은 옛 테마에서 받은 크기를 키우지 않는다. 처음에는 56px을 72px로 올려 보았으나 옛 장면 코드가 본문을 제목 아래 고정 y에 두어 9곳이 겹쳤다(ch02 s02, ch03 s03·s09, ch04 s02·s05·s07·s08·s09). 큰 제목은 레이아웃 부품과 장면 코드의 `size`로 정한다.

## 3. 레이아웃

장마다 `plan/themes.md` 6절 「레이아웃 목록」의 16가지 가운데 하나를 고른다. 자리와 크기, 등장 방식은 그 절에 있다.

배치 규칙(줄임, 전문은 `plan/themes.md` 6절):

1. 이웃한 장에 같은 레이아웃을 쓰지 않는다. 챕터마다 다섯 가지 이상.
2. 핵심 요소는 화면의 3분의 1 이상.
3. 끝 상태에서 화면의 위쪽 절반이나 아래쪽 절반이 비어 있으면 안 된다. 머리말과 출처 줄만 있는 절반은 빈 것으로 센다.
4. 장 제목 72px, 설명 글자 34px 이상, 짚는 이름표 34px 이상, 그린 화면 안 글자 30px 이상, 표의 행 글자 34px 이상. 30px은 출처와 머리말에만 쓴다.
5. 표는 한 장에 5행 안팎이고 6\~8행이면 「화면 전체」(36px, 행 높이 82)나 「두 장으로 나눔」을 배정표에 적는다.
6. 한 장에 주황 면은 두 곳까지. 승인은 연두, 구조와 강조는 주황.
7. `steps`는 기본 `[]`이고 답을 먼저 보이면 안 되는 장에만 한 번.
8. 장마다 한 곳을 크게 강조한다(주황 면 하나 또는 100px 이상의 글자). 핵심 요소는 y 240\~900 이상을 쓴다.

## 4. 부품

모두 `setup`에서 부르고, 돌려받은 객체의 `render(lt, ctx)`를 슬라이드의 `render`에서 부른다. 좌표는 1920×1080 무대 px다. 이름과 인자는 처음 테마와 같다. 처음 테마의 인자 가운데 `frost`, `edge`, `beam`, `seed`, `depth`의 떠다니기는 받아도 무시한다.

### 그린 화면 조각

`THEME.shot`의 `draw` 안에서 ChatGPT 화면을 그릴 때 쓰는 클래스다: `.p3-ui-pill`(위쪽 메뉴 단추, 40px), `.p3-ui-comp`(입력 칸), `.p3-ui-file`(붙인 파일, 36px), `.p3-ui-plus`(+ 단추, 64px), `.p3-ui-send`(보내기 단추, 64px). 단추 이름은 `plan/tool_facts.md` 표기를 그대로 쓴다. 화면 전체를 줄여 그리지 않고 짚을 부분만 크게 그린다. 본보기는 ch00 s05(Work 단추와 입력창만 그렸다).

### 화면 캡처(`THEME.shot`)

- 경로는 `deck/assets/p3/shots/<슬라이드 id>.png` 하나다. 파일이 없으면 `src`를 `null`로 두고 `chat`이나 `draw`로 그린 화면을 넣는다. 없는 파일의 경로를 걸어 두면 `check`가 오류로 잡는다.
- 짚을 곳은 `marks`로 주황 테두리를 얹는다. 캡처에서는 화면 기준 비율 `{ x, y, w, h }`, 그린 화면에서는 `{ pick: d => … }`로 요소를 고른다.
- 버튼 이름과 입력할 글은 화면 옆 글 열이 아니라 화면 위 빈 자리의 짚는 말(`callout`, 34px)로 다시 쓴다.
- 캡처 속 글자가 화면에 놓였을 때 30px 아래가 되면 필요한 부분만 더 좁게 잘라 쓴다.
- 캡처는 ChatGPT 어두운 화면 모드로 찍기를 권한다.

## 7. 하지 않는 것

1. 연두를 승인 표시 밖에서 쓰지 않는다. 한 장에 주황 면을 세 곳 이상 두지 않는다.
2. HUD 요소(모서리 브래킷, 타임코드, 영문 대문자 모노체 라벨, 진행 막대 장식)를 넣지 않는다. 챕터 표시는 「파트 3 · n장」으로 쓴다.
3. 유리 판, 배경 흐림(`backdrop-filter`), 그림자, 그라디언트 면, 무지개 띠, 보라, 빛 번짐을 쓰지 않는다.
4. 왼쪽에 작은 카드를 쌓고 오른쪽을 비우는 구도, 위쪽이나 아래쪽 절반을 비우는 구도를 쓰지 않는다. 핵심 요소를 화면의 3분의 1 이상으로 키운다.
5. 읽어야 하는 글자를 기울이거나 흐리게 두지 않는다. 30px 아래로 내리지 않는다.
6. CSS `transition`·`animation`·`@keyframes`, `Math.random`, 타이머를 쓰지 않는다. 움직임은 모두 `render(lt)`가 계산한다.
